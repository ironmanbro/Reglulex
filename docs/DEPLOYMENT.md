# Deployment

## What you need

| Component | Recommended | Notes |
|---|---|---|
| Web service | Render / Railway / Fly.io / any Docker host | `entrypoint web`, port `$PORT`, health check `/api/health` |
| Worker | Same platform, background worker | `entrypoint worker` (long-running). Use `entrypoint worker-once` on a cron if your platform only offers scheduled jobs (e.g. every 15 min). |
| PostgreSQL 14+ | Managed, with daily backups / PITR | Extensions `pg_trgm`, `unaccent` (created by the first migration) |
| Object storage | Cloudflare R2 (no egress fees) or AWS S3 | Private bucket; the app serves files itself |

## Option A — Render (blueprint included)

1. Push this repository to GitHub.
2. In Render: **New → Blueprint** → select the repo. `render.yaml` creates the database, web service and worker.
3. Create an R2 (or S3) bucket and an access key limited to that bucket.
4. Fill in the secrets Render asks for:
   - `S3_BUCKET`, `S3_ENDPOINT` (R2: `https://<account-id>.r2.cloudflarestorage.com`), `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`
   - `ADMIN_PASSWORD_HASH`: run `pnpm admin:hash-password` locally and paste the output
   - `PUBLIC_SITE_URL`: e.g. `https://fi-library.onrender.com` or your domain
   - `ALERT_WEBHOOK_URL` (optional): Slack/Discord incoming webhook
5. Deploy. The web service applies migrations and seeds the source registry on start.
6. Copy the web service's `SESSION_SECRET` (generated by Render) only if you later add more web instances; the worker does not need it.

## Option B — single VM with Docker Compose

```bash
cp .env.example .env    # set ADMIN_PASSWORD_HASH, SESSION_SECRET, PUBLIC_SITE_URL (and POSTGRES_PASSWORD)
docker compose run --rm web node_modules/.bin/tsx scripts/hash-password.ts   # prints ADMIN_PASSWORD_HASH
docker compose up -d --build
```

Put a TLS-terminating reverse proxy (Caddy, nginx) or a Cloudflare Tunnel in front of port 3000. The volumes `pgdata` (database) and `originals` (original files) hold all state, so back them up (below). To keep originals in S3/R2 instead, set `STORAGE_DRIVER=s3` and the `S3_*` variables in `.env`.

## Go-live checklist

- [ ] `DATABASE_URL` points to a managed database with automated backups enabled
- [ ] `STORAGE_DRIVER=s3` and the bucket is private (never `local` in production: container disks are ephemeral)
- [ ] `ADMIN_PASSWORD_HASH` and `SESSION_SECRET` (≥32 random chars) set; admin login works
- [ ] `PUBLIC_SITE_URL` set (citations, sitemap)
- [ ] Web `/api/health` returns `{"status":"ok"}`
- [ ] Worker is running: `/admin` shows "Last job finished …" updating
- [ ] First collection: in `/admin`, press **Crawl now** on each enabled source; check `/admin/runs`
- [ ] For each source: status **Working**, or a recorded failure you have triaged (update its config, or leave it disabled)
- [ ] Run **Backfill** for sources with archives (SEBI listings, RBI Master Directions, DPIIT, IFSCA)
- [ ] Spot-check 5 documents: official link opens, archived PDF displays, text is searchable
- [ ] `ALERT_WEBHOOK_URL` tested (temporarily break a source URL and watch for the alert)
- [ ] Review each source's terms of use / copyright notice. If an authority does not permit redistribution, set `SERVE_ORIGINAL_FILES=false` (site-wide) so only metadata, text and official links are shown.
- [ ] Custom domain and TLS configured

## Backups and restore

**Database** (all metadata, text, versions, relationships, audit):

```bash
# backup (logical, consistent snapshot)
pg_dump --format=custom --no-owner "$DATABASE_URL" > fi_library_$(date +%F).dump
# restore into an empty database
pg_restore --no-owner --dbname "$NEW_DATABASE_URL" fi_library_2026-10-24.dump
```

Managed providers' automated daily backups / PITR should be enabled as well. Keep at least one off-platform dump per week.

**Original files** (S3/R2): object keys are content-addressed (`originals/ab/<sha256>.pdf`) and never overwritten, so a bucket replica or a periodic `rclone sync` / `aws s3 sync` to a second bucket is a complete backup. Enable bucket versioning where available. With Docker Compose and local storage, back up the `originals` volume, e.g. `docker run --rm -v reglulex_originals:/d -v $PWD:/b alpine tar czf /b/originals.tgz -C /d .`

**Restore drill**: restore the dump into a scratch database, point a local `pnpm dev` at it with the same bucket (read-only key), and open a few documents.

## Scaling notes

- Run more worker replicas if collection falls behind; job claiming is lock-free (`SKIP LOCKED`) and scheduling is deduplicated. The per-host politeness delay is per process, so with N workers a host may see up to N requests per interval. Keep `CRAWLER_MIN_INTERVAL_MS` conservative.
- The in-memory API rate limiter is per web instance.
